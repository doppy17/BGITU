# Локальная LLM в поиске БГИТУ

Поиск остаётся прежним: индекс `#bgitu-index` и мгновенный подстрочный фильтр в
`static/js/search.js`. LLM — необязательная надстройка, которая **переранжирует
2–6 спорных кандидатов** в выпадающих подсказках. Если модель не загрузилась,
не успела или упала — подсказки отдаёт обычный локальный поиск.

Внешних демонов и сети нет: модель работает внутри процесса Django через
[`llama-cpp-python`](https://github.com/abetlen/llama-cpp-python) (llama.cpp).

## Что установлено

| Компонент | Значение |
|---|---|
| Рантайм | `llama-cpp-python==0.3.38` (сборка из исходников, Metal на Apple Silicon) |
| Модель | `Qwen2.5-1.5B-Instruct`, GGUF `Q4_K_M`, ~1.0 ГБ |
| Файл | `models/qwen2.5-1.5b-instruct-q4_k_m.gguf` (в git не хранится) |
| Контекст | `n_ctx=2048`, `n_threads=8`, `temperature=0.2` |

## Установка

`pip` в рабочем venv нет (venv создан через `uv`), поэтому ставим через `uv`:

```bash
cd /Users/main/Documents/BGITU

# 1. Рантайм (сборка ~5–10 минут, нужны Xcode Command Line Tools)
~/.hermes/bin/uv pip install \
  --python ~/.hermes/cache/scratch/lk-run/.venv/bin/python \
  llama-cpp-python

# 2. Модель (~1 ГБ, качается один раз)
mkdir -p models
curl -L --fail --retry 3 \
  -o models/qwen2.5-1.5b-instruct-q4_k_m.gguf \
  "https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct-GGUF/resolve/main/qwen2.5-1.5b-instruct-q4_k_m.gguf"

# 3. Проверка
~/.hermes/cache/scratch/lk-run/.venv/bin/python manage.py check
```

`models/` добавлен в `.gitignore` — гигабайтный файл в репозиторий не попадает.
Путь к модели вычисляется от `settings.BASE_DIR`, поэтому проект переносим.

## Как работает

```
ввод → локальный фильтр (0 мс) → debounce 180 мс → GET /api/search/suggest/?q=
                                                   ├─ prefilter (подстрока + fuzzy)
                                                   ├─ 2–6 кандидатов → LLM-ранжирование (таймаут 1.4 с)
                                                   └─ иначе/ошибка → локальный порядок
```

* `apps/core/local_llm.py` — ленивый singleton: импорт модуля модель **не** грузит,
  первый `ask()` загружает её (~2–5 с) в фоновом потоке. Генерация ограничена
  `max_tokens` и не блокирует другие запросы: если модель занята, `ask()`
  сразу возвращает `None`, и поиск идёт по локальному результату.
* `apps/site/suggest.py` — prefilter по тому же набору разделов, что и
  `#bgitu-index` (страницы сайта + кабинет), плюс вызов LLM и разбор ответа.
  Любое исключение → `{"items": []}` либо локальный список, но не 500.
* `apps/core/ai_views.py` + `/api/ai/status/` — диагностика только для staff.

## Разбор файлов

ИИ-разбор импортированных файлов устроен так же, как поиск: **факты считает
Python, модель пишет только короткое резюме**. Поэтому числа в отчёте всегда
совпадают с базой, а при недоступной модели разбор продолжает работать.

### Что считается кодом

`apps/schedule/ai_review.py` разбирает занятия источника и проверяет:

* сколько занятий, групп, преподавателей, аудиторий и дисциплин;
* распределение по неделям (каждую / 1-я / 2-я) и видам занятий;
* группы из шапки файла, у которых нет ни одной пары;
* пересечения: одна аудитория или преподаватель в одно время у разных групп,
  два занятия у группы в один слот. Потоковая лекция (та же дисциплина, тот же
  преподаватель, та же аудитория) конфликтом не считается;
* пары вне сетки (дни 1–6, пары 1–8) и пары без звонка в корпусе;
* подозрительные строки: служебные названия, цифры в ФИО, необычные коды групп;
* для плана — дисциплины без семестра, семестры вне 1–8, дубли, пропуски
  семестров и служебные строки.

Резюме модели ограничено: **≤ 5 пунктов, ≤ 500 символов**. Дополнительно
отбрасываются пункты, где встречается число, которого нет в фактах, — защита
от выдуманных счётчиков. Промпт просит опираться только на раздел «Требует
внимания».

### Команда

```bash
python manage.py ai_review_schedule \
  --file fixtures/schedule/bgitu-2026-27-1semestr-IVT-IST-PI-PRI.xls \
  --plan fixtures/plan/plan.json
```

* `--file` — расписание `.xls/.xlsx`. Если файл уже импортирован, цифры берутся
  из его занятий в БД; иначе файл разбирается на лету, без записи в базу.
* `--plan` — план `.xls/.xlsx/.docx/.pdf` или JSON фикстуры.
* `--no-llm` — только факты, без резюме (быстро и детерминированно).
* `--out` — папка отчётов, по умолчанию `docs/ai-reviews`.

Без аргументов команда разбирает последний импорт. Отчёт сохраняется в
`docs/ai-reviews/<дата>-<файл>.md`, разбор печатается в консоль.

### В личном кабинете

На `/schedule/import/` staff и developer видят панель «ИИ-разбор». Страница не
ждёт модель: блок сразу показывает факты, а резюме подгружается асинхронно
через `POST /schedule/import/ai-review/<id>/` (JSON). Кнопка «разбор» в строке
истории переключает панель на любой другой импорт. Если модель недоступна,
блок остаётся с фактами и пометкой «локальная модель недоступна».

`apps/schedule/llm_client.py` не создавался: используется общий рантайм
`apps/core/local_llm.ask` через ленивый импорт внутри `ask_local`. Если модуля
ещё нет, вызывается заглушка, возвращающая `None`, — после появления рантайма
импорт подхватывается автоматически.
