# БГИТУ-портал — сайт и личный кабинет на Django

Единый проект: публичный сайт БГИТУ (макет из архива, 39 страниц) и личный
кабинет с настоящей базой данных, ролями и правами, курсами, работами,
оценками, посещаемостью и расписанием из файла университета.

- **Стек:** Python 3.11, Django 5.2 LTS, SQLite (по умолчанию), серверные шаблоны + дизайн-система статического макета.
- **Без внешних сервисов:** всё работает локально, никаких API ЭОС и облаков.
- **Данные:** занятия и группы — из файла `bgitu.ru` (1 семестр 2026/27), остальное — демо-данные.

## Запуск

Проще всего — из корня проекта одной командой (сама создаст `.venv`, поставит зависимости,
применит миграции, засеет демо-данные при первом запуске и поднимет сервер):

```bash
cd "$HOME/Documents/BGITU"
./run.sh              # следующий свободный порт из .run-port + браузер
./run.sh --no-open    # без браузера
make run              # то же через make
```

Вручную отсюда же:

```bash
cd "$HOME/Documents/BGITU"
./.venv/bin/python manage.py migrate
./.venv/bin/python manage.py seed_demo          # роли, пользователи, курсы, расписание
./.venv/bin/python manage.py runserver 127.0.0.1:8010
```

Если окружение потерялось (в PATH нет `uv` — он в `~/.hermes/bin/uv`):

```bash
"$HOME/.hermes/bin/uv" venv --python 3.11 .venv
"$HOME/.hermes/bin/uv" pip install --python .venv/bin/python -r requirements.txt
```

Открыть `http://127.0.0.1:8010/` — редирект на вход. Пароль всех демо-аккаунтов: `demo12345`.

## Регистрация

`/register/` — самостоятельное создание кабинета: фамилия и имя, логин, e-mail,
группа (необязательно), пароль. После отправки создаётся `User` + `Profile`,
назначается роль «Студент», выполняется вход и редирект в `/cabinet/`.
Проверяются уникальность логина и e-mail, формат, совпадение паролей и
стандартные валидаторы Django. Другую роль пользователь запрашивает в `/roles/`.

## Публичный сайт

Макет из архива, разложенный в Django-шаблоны:

| URL | Страница |
|---|---|
| `/` | главная |
| `/university/`, `/institutes/`, `/inst-*/` | университет и институты |
| `/admission/`, `/programs/`, `/program/` | приёмная кампания |
| `/student/`, `/timetable/`, `/eos/`, `/help/` | студенту (расписание занятий публичное) |
| `/news/`, `/article/`, `/contacts/` | новости и контакты |

Кнопка «Личный кабинет» в шапке ведёт в `/cabinet/`. Страницы собираются
скриптом из архива:

```bash
python scripts/build_static_site.py ~/Downloads/bgitu-site-main
```

Скрипт кладёт общий CSS/JS в `static/site/`, режет страницы на шаблоны
`apps/site/templates/site/pages/*.html`, подставляет `{% url %}`/`{% static %}`
и обновляет реестр `apps/site/pages.py`. Вьюха одна — `PageView`.

## Расписание

Файл скачан с сайта БГИТУ: [очное обучение, 1 семестр 2026/27, группы ИВТ/ИСТ/ПИ/ПрИ](https://bgitu.ru/studentu/raspisanie/ochnoe-obuchenie/2026-27/1-semestr/v8/) → `fixtures/schedule/bgitu-2026-27-1semestr-IVT-IST-PI-PRI.xls` (81 КБ, сохранён 02.10.2026).

- Парсер `apps/schedule/import_service.py` читает шапку с группами, дни, пары, подгруппы; из ячейки выделяет дисциплину, аудиторию и преподавателя.
- Импорт: `python manage.py import_schedule <файл.xls>` или через страницу `/schedule/import/` (право `can_manage_schedule`). Можно загрузить сразу несколько файлов разных институтов.
- Каждый файл — отдельный источник `ScheduleImport` (имя, институт/охват, дата, автор, размер, счётчики). Повторная загрузка файла того же института заменяет его занятия; файлы разных институтов живут одновременно.
- При конфликте слота (группа, день, пара, подгруппа) показывается занятие из самого свежего по дате загрузки файла; более старые остаются в БД и вернутся, если свежий файл удалить.
- Результат текущего файла: **265 занятий, 12 групп**. Для ИСТ-201 — 20 занятий в неделю, включая подгруппы (п/г 1/2).
- Студент видит расписание своей группы; сотрудник с правом управления расписанием может переключать группы.

## Ограничения демо

- SQLite и локальные файлы; для прода — PostgreSQL (`DB_ENGINE=postgres`) и S3/volume, настройки в `config/settings/prod.py`.
- Один активный роль-профиль; нет SSO, почтовых уведомлений и интеграции с ЭОС.
- Расписание обновляется вручную импортом файла, автоматической синхронизации с bgitu.ru нет.
- Стипендия рассчитывается упрощённо (базовая + ×1,8 при среднем ≥4,5), без ПГАС и социальных выплат.
- Файлы работ принимаются до 20 МБ, расширения: pdf, doc(x), zip, rar, txt, py, xlsx, png, jpg.

## Деплой на Render

Прод-конфигурация лежит в `config/settings/render.py` + `render.yaml`
(web-сервис и managed Postgres создаются одним Blueprint):

```
https://render.com/deploy?repo=https://github.com/doppy17/BGITU
```

Что делает `build.sh`: ставит зависимости, `collectstatic`, `migrate`, `seed_demo`.
База берётся из `DATABASE_URL` (Render подставляет строку подключения сам;
вместо Render Postgres можно указать Neon — код не меняется).
Статику отдаёт WhiteNoise, приложение — gunicorn.
Загрузки работ лежат на эфемерном диске и теряются при передеплое.
